Runnable companions to xref:../LLM_Observability_AWS.adoc[LLM Observability on AWS].

[source,bash]
----
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

export ENVIRONMENT=dev
export SESSION_TABLE=llm-sessions
export ANTHROPIC_API_KEY=sk-ant-...

uvicorn app:app --port 8080

curl -s localhost:8080/chat \
  -H "Authorization: Bearer devtoken123" \
  -H 'Content-Type: application/json' \
  -d '{"message":"hello"}'
----

Each request prints two kinds of line to stdout: structured JSON logs, and EMF
records that CloudWatch turns into metrics once the awslogs driver ships them.
Locally you just see the JSON — which is the point, the same records work in
both places.

== Reading order

[source,text]
----
context.py            # the identity chain everything else depends on
  └─ emf.py           # how a metric reaches CloudWatch, and the cardinality rule
     └─ litellm_callback.py   # where cost, tokens and model timing are captured
        └─ sessions.py        # session created in FastAPI, id shared with LiteLLM
           └─ app.py          # it all wired together
              └─ alarms.py    # alarms on metrics, queries on properties
----

`ecs_task_definition.json` carries the deployment-side notes — log driver mode,
secrets, task-role permissions, and why there is no `cloudwatch:PutMetricData`.

== Verified

`emf.py` is executed and asserted in isolation (record shape, dimension sets,
single-line output, the dimension/property overlap guard). The rest is
syntax-checked only — the AWS and LiteLLM paths need credentials and a live
account to exercise.
