== Build Order

Techniques are not equally valuable. This is the order that returns the most
per unit of effort:

. *Fix the parser and the chunker* — xref:RAG_Chunking.adoc[Chunking]. Nothing
  downstream can recover from garbled input.
. *Add BM25 and fuse with RRF* — xref:RAG_Hybrid_Search.adoc[Hybrid Search].
  Thirty lines; covers dense search's blind spot for IDs and acronyms.
. *Add a cross-encoder reranker* — xref:RAG_Reranking.adoc[Reranking]. The single
  biggest accuracy jump per line of code.
. *Build an eval set* — xref:RAG_Evaluation.adoc[Evaluation]. Not an accuracy
  win; it is what tells you whether 1-3 helped. *Do not skip this.*
. *Add citations* — xref:RAG_Citations.adoc[Citations]. Changes whether anyone
  can act on the answer.
. *Handle follow-ups* — xref:RAG_Conversational_Memory.adoc[Conversational
  Memory]. Turn 2 is broken without it.
. *Close the security gaps* — xref:RAG_Security.adoc[Security]. Retrieved
  documents are untrusted input, and access control has to be a pre-filter
  before there is production data behind it.
. *Trace every answer* — xref:RAG_Operations.adoc[Production Operations]. RAG
  degrades silently, so the ability to ask "why did it say that?" is what makes
  everything above debuggable once real users arrive.

Everything after that — Contextual Retrieval, Parent-Child, RAG-Fusion, agentic
loops — is worth measuring against your own eval set *and* your
xref:RAG_Cost_Latency.adoc[latency budget] before shipping.

== Running the Examples

[source,bash]
----
cd examples
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...        # only for generation examples

python naive_rag.py "how do I roll back a payments deploy?"
python hybrid_search.py "what is a PIT?"
python cross_encoder_rerank.py
python production_rag_pipeline.py
----

The shared corpus in `examples/_common.py` is six chunks chosen to be adversarial
on purpose — a once-only acronym, a numeric fact, two near-duplicates, and a
paraphrase gap — so each technique's win or loss is visible in one terminal
screen.

== Key Ideas, in One Table

[cols="1,3", options="header"]
|===
|Idea |Why it recurs

|*Recall then precision*
|Cheap-and-broad before expensive-and-narrow: 1M chunks → 50 candidates → 5 chunks. A reranker can only reorder what retrieval gave it.

|*Anti-correlated retrievers fuse well*
|Dense and BM25 fail on opposite inputs. That is the whole argument for hybrid search.

|*Chunks lose their context*
|Every advanced chunking technique — Parent-Child, Contextual Retrieval, Late Chunking, sentence windows — is a different answer to this one problem.

|*Rank, don't score*
|BM25 scores are unbounded and cosine sits in [-1,1]. RRF fuses ranks, so no calibration is needed.

|*Verify, don't trust*
|A citation you cannot check mechanically is decoration. Require a verbatim quote and test that it exists.

|*Measure or guess*
|Every table in these documents ends the same way: run it on your own corpus. Ablation is the only honest answer.
|===
