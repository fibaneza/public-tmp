== Technique Collections

The best starting points — each covers many techniques with runnable notebooks.

* link:https://github.com/NirDiamant/RAG_Techniques[NirDiamant/RAG_Techniques] —
  the most comprehensive single collection: 30+ techniques, each with a notebook
  and an explanation. Start here.
* link:https://github.com/Jeevav62/Rag-techniques[Jeevav62/Rag-techniques] —
  compact walkthroughs of the core technique set.
* link:https://github.com/topics/advanced-rag[GitHub topic: advanced-rag] — the
  live feed of what people are publishing.
* link:https://github.com/topics/rag[GitHub topic: rag] ·
  link:https://github.com/topics/retrieval-augmented-generation[topic: retrieval-augmented-generation]
* link:https://github.com/athina-ai/rag-cookbooks[athina-ai/rag-cookbooks] —
  advanced RAG cookbooks with evaluation built in.
* link:https://github.com/Danielskry/Awesome-RAG[Danielskry/Awesome-RAG] ·
  link:https://github.com/frutik/Awesome-RAG[frutik/Awesome-RAG] — link collections.
* link:https://github.com/hymie122/RAG-Survey[hymie122/RAG-Survey] — papers
  organised by the survey's taxonomy.

== Hierarchical and Structured RAG

* link:https://github.com/pheonix-delta/WiredBrain-Hierarchical-Rag[pheonix-delta/WiredBrain-Hierarchical-Rag] —
  hierarchical retrieval over a document tree.
* link:https://github.com/parthsarthi03/raptor[parthsarthi03/raptor] — RAPTOR
  reference implementation (recursive clustering + summarisation).
* link:https://github.com/microsoft/graphrag[microsoft/graphrag] — the GraphRAG
  reference implementation, including global map-reduce search.
* link:https://github.com/HKUDS/LightRAG[HKUDS/LightRAG] — a much lighter graph
  RAG.
* link:https://github.com/circlemind-ai/fast-graphrag[circlemind-ai/fast-graphrag] —
  PageRank-based graph retrieval.
* link:https://github.com/neo4j-labs/llm-graph-builder[neo4j-labs/llm-graph-builder] —
  build a knowledge graph from documents.

== Reranking

* link:https://github.com/FlagOpen/FlagEmbedding[FlagOpen/FlagEmbedding] — BGE
  embeddings *and* the `bge-reranker` family.
* link:https://github.com/UKPLab/sentence-transformers[sentence-transformers] —
  `CrossEncoder`, the standard local reranking API.
* link:https://github.com/AnswerDotAI/rerankers[AnswerDotAI/rerankers] — one
  interface over cross-encoders, ColBERT, LLM rerankers and hosted APIs.
* link:https://github.com/stanford-futuredata/ColBERT[stanford-futuredata/ColBERT] ·
  link:https://github.com/AnswerDotAI/RAGatouille[RAGatouille] (friendly wrapper)
* link:https://github.com/castorini/rank_llm[castorini/rank_llm] — listwise LLM
  reranking (RankGPT, RankZephyr).
* link:https://www.pinecone.io/learn/series/rag/rerankers/[Pinecone: rerankers] —
  a good conceptual explainer.

== Frameworks and Orchestration

* link:https://github.com/langchain-ai/langchain[langchain-ai/langchain] ·
  link:https://github.com/langchain-ai/langgraph[langgraph] — the graph library is
  the more useful half for agentic RAG.
* link:https://github.com/run-llama/llama_index[run-llama/llama_index] — the
  strongest set of RAG-specific abstractions (routers, node postprocessors,
  query engines).
* link:https://github.com/deepset-ai/haystack[deepset-ai/haystack] — explicit
  pipeline graphs; production-oriented.
* link:https://github.com/stanfordnlp/dspy[stanfordnlp/dspy] — compile prompts
  and pipelines against a metric instead of hand-tuning them.
* link:https://github.com/microsoft/semantic-kernel[microsoft/semantic-kernel]
* link:https://github.com/infiniflow/ragflow[infiniflow/ragflow] — deep document
  understanding, deployable end to end.
* link:https://github.com/Mintplex-Labs/anything-llm[Mintplex-Labs/anything-llm] ·
  link:https://github.com/open-webui/open-webui[open-webui] — full applications
  worth reading for their document-management UX.
* link:https://github.com/pathwaycom/llm-app[pathwaycom/llm-app] — streaming /
  always-fresh indexes.
